# REPLACE_WITH_TASK_TITLE

## Outcome

Describe the user's intended result and why it matters. Include the expected
observable behavior; preserve important wording from the discussion.

## Current state and evidence

Summarize relevant source inspection, reproduction, or measurements. Link the
implementation, maintained docs, and related tasks using repository-relative
paths. Identify hypotheses and dated evidence explicitly.

## Agreed decisions and scope

Record the choices settled with the user, relevant defaults, boundaries, and any
dependencies. State what this task includes and any exclusion needed to prevent
likely scope creep. Do not substitute a different design for the agreed choice.

## Implementation approach

Describe the bounded changes, affected interfaces and ownership, and relevant
edge cases. Provide enough direction to avoid another product-design discussion,
while leaving routine coding details to the implementer.

## Acceptance and verification

- [ ] Replace with concrete expected behavior and how to check it.
- [ ] Replace with applicable automated, rendered, or performance checks.
- [ ] Replace with required documentation and committed/pushed delivery evidence.

Human acceptance: state what requires the user's playtest, controller, listening,
or visual review; say whether it is a completion gate or a follow-up. Remove this
paragraph when it does not apply. Never equate automated checks with human review.

## Open questions

Use `None` for a ready task. For a requested draft, list the unanswered decisions
that prevent implementation. Required pre-implementation decisions must be
resolved before changing the status to ready.

## Completion record

Pending implementation. The worker should record the outcome, verification
actually performed, remaining acceptance, updated documentation, and commit/push
references. If blocked, record the blocker and unfinished work instead of success.
Link any separate next-step proposals in `backlog/ideas/`, or note that none were
proposed. Those suggestions require the user's selection before task authoring.
